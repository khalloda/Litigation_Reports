# Document Upload API Documentation

## Overview

The `/api/documents` POST endpoint handles file uploads for the litigation management system.

## Endpoint Details

### URL

```
POST /api/documents
```

### Content-Type

```
multipart/form-data; boundary=<auto-generated>
```

**IMPORTANT**: Do NOT manually set the `Content-Type` header when using FormData. The browser automatically sets it with the proper boundary parameter.

### Authentication

```
Authorization: Bearer <token>
```

## Request Parameters

### Required Fields

| Field | Type | Description |
|-------|------|-------------|
| `file` | File | The document file to upload |
| `title` | String | Document title (required) |

### Optional Fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `description` | String | `""` | Document description |
| `document_type` | String | `"other"` | Type of document |
| `entity_type` | String | `null` | Related entity type |
| `entity_id` | String | `null` | Related entity ID |
| `is_public` | Boolean | `false` | Whether document is public |
| `tags` | String | `""` | Comma-separated tags |

## File Constraints

### Supported File Types

- PDF (.pdf)
- Microsoft Word (.doc, .docx)
- Text files (.txt)
- Images (.jpg, .jpeg, .png, .gif)

### Size Limits

- Maximum file size: 10MB
- Server limits: Check `php.ini` settings:
  - `upload_max_filesize`
  - `post_max_size`

## Common Issues and Solutions

### Issue 1: 400 Bad Request with "No file uploaded"

**Cause**: Incorrect `Content-Type` header
**Solution**: Remove manual `Content-Type` header when using FormData

### Issue 2: Upload validation fails despite filled form

**Cause**: Wrong input selector in tests/automation
**Solution**: Use specific selectors like `.modal input[type="text"]` instead of `input[type="text"].first()`

### Issue 3: API service treats FormData as JSON

**Cause**: API service doesn't detect FormData objects correctly
**Solution**: Check for `instanceof FormData` before `hasFileFields()`

## Security Considerations

1. **File Type Validation**: Server validates file types
2. **Size Limits**: Enforced at both client and server
3. **Authentication**: Required for all uploads
4. **Path Security**: Files stored outside web root
5. **Unique Filenames**: Prevents conflicts and overwrites

## Storage Location

Files are stored in:

```
backend/uploads/documents/
```

With filename format:

```
{uniqid}_{timestamp}.{extension}
```

Example: `68d280eddcfa3_1758626029.pdf`
